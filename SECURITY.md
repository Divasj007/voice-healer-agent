# Security Policy

## Scope

Voice Healer is a local developer tool that executes Python files and can apply code generated by a local language model. Treat generated repairs as untrusted until they have been reviewed and verified.

## Supported versions

Security fixes target the latest `main` branch and the latest release.

## Reporting a vulnerability

Please use GitHub's private security advisory workflow for this repository rather than opening a public issue with exploit details.

When reporting, include the affected file or endpoint, reproduction steps, impact, and the smallest relevant log or traceback. Do not include credentials, private source code, or personal data.

## Security design principles

- The main CLI keeps target paths inside the repository.
- The UI binds only to loopback addresses and validates repository-relative paths. Non-loopback bind addresses are rejected.
- The voice/Git command parser exposes a narrow allow-list instead of arbitrary shell commands.
- Ollama communication uses a loopback-only REST endpoint; embedded credentials and non-loopback URLs are rejected.
- Model-generated Python is parsed with the AST before it is written.
- The Safety Guard compares the proposed candidate with the current source and blocks newly introduced shell execution, network access, credential access, dynamic code execution, destructive deletion, unsafe pickle deserialization, native-code loading, and unsafe path writes.
- Interactive approval re-runs the Safety Guard on the stored candidate immediately before applying it, so the HTTP approval endpoint cannot bypass the browser-level decision gate.
- Repairs are written atomically and the original source is backed up before patching.
- Failed verification restores the original file.
- The project does not accept secrets or model credentials through source-controlled configuration.
